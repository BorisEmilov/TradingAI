Estos son los endpoints que no existian en la version monousuario. Son la puerta de entrada de la API: sin un token de /auth/login ninguno de los otros 41 responde.

POST /auth/refresh requiere token

Renovar la sesion sin reenviar credenciales

Reinicia el reloj de **vida maxima** de la sesion.

El token **no cambia**: se sigue usando el mismo, con lo que no hay carrera con peticiones en vuelo. Solo se reinicia el contador.

Cuando hace falta:

- La ventana de **inactividad** (15 min) ya se renueva sola con cualquier llamada autenticada. Para eso no hace falta este endpoint. - El tope de **vida maxima** (1 h) NO se renueva solo. Un cliente que este conectado toda la sesion bursatil debe llamar aqui cada cierto tiempo (p.ej. cada 30 min) para no verse obligado a reenviar las credenciales.

Si prefieres que no exista tope absoluto, arranca con `PYGW_SESSION_TTL=0`: entonces la sesion solo muere por inactividad y este endpoint es opcional.

3. Como esta montado (y por que)

El problema que resuelve esta arquitectura. La libreria MetaTrader5 de Python es un singleton de proceso: mt5.login() cambia la cuenta de todo el proceso y de su terminal. Si varios usuarios compartieran proceso, el login de uno cambiaria la sesion de otro, y un «cerrar posicion» podria ejecutarse contra la cuenta equivocada. Verificado: dos procesos atados al mismo terminal comparten cuenta.

Por eso cada sesion recibe su propio terminal MT5 y su propio proceso. Es la unica forma de servir N cuentas a la vez.

Cliente .NET (usuario A) Cliente .NET (usuario B) | | | HTTP + Authorization: Bearer <token> v v +---------------------------------------------+ | GATEWAY (Python de Linux, async) | /auth/*, sesiones, pool +---------------------------------------------+ | reenvio interno por localhost v v WORKER slot-1 (Wine) WORKER slot-2 (Wine) | | terminal MT5 propio terminal MT5 propio data_path: C:\mt5-instances\slot-1 ...\slot-2 | | cuenta del usuario A cuenta del usuario B

El gateway corre en el Python de Linux: solo enruta, no necesita la libreria MT5 y gana concurrencia real. Los workers corren bajo Wine, que es donde vive la DLL del terminal.

4. Autenticacion en detalle

Cada usuario aporta sus propias credenciales MT5. El flujo tiene tres pasos:

1. POST /auth/login {login, password, server} -> { "token": "...", ... } 2. Cualquier endpoint con Authorization: Bearer <token> 3. POST /auth/logout (o dejar que caduque) -> libera el terminal

4.1 Que pasa con la contrasena

No se guarda en ningun sitio. Viaja una sola vez del cliente al worker, se usa para autenticar el terminal y se descarta. No se escribe en disco, ni en los logs, ni queda en memoria del gateway. Lo unico que persiste mientras dura la sesion es el token y a que slot apunta.

Consecuencia asumida: si el gateway se reinicia, todos los usuarios vuelven a autenticarse. Es el precio de no ser un almacen de credenciales.

TLS es obligatorio si sales de localhost. Con --host 0.0.0.0 y sin HTTPS delante, las credenciales MT5 de tus usuarios viajan en claro. Pon un reverse proxy (nginx, Caddy, Traefik) con certificado. El gateway no termina TLS por si mismo, a proposito: esa responsabilidad es del proxy.

4.2 Ciclo de vida del token

ConceptoValor por defectoDetalle
Vida maxima3600 sDesde el login, pase lo que pase.
Inactividad900 sVentana deslizante: cada peticion la renueva.
Caducidad efectiva—La que llegue antes de las dos. Va en expires_at / expires_in.
Al caducar—Un barrido cierra la sesion y libera el slot. Sin esto, un cliente que se desconecta sin logout agotaria el pool.

Un login con una cuenta que ya tiene sesion viva devuelve la misma sesion (reused: true) en lugar de consumir un segundo slot.

5. Convenciones de datos

5.1 Fechas y horas

MT5 devuelve los tiempos como epoch en segundos, pero medidos con el reloj del servidor del broker, no en UTC. El gateway no inventa una conversion de zona horaria. Cada campo temporal se expone dos veces:

CampoTipoEjemploSignificado
timeinteger (int64)1789037400Epoch crudo, tal cual lo da MT5.
time_isostring"2026-09-10T14:30:00"El mismo instante formateado, sin sufijo Z.
time_mscinteger (int64)1789037400123Epoch en milisegundos (ticks y deals).
En .NET: deserializa time_iso como DateTime con DateTimeKind.Unspecified. La ausencia deliberada de Z senala que es hora de servidor. Si necesitas UTC real, aplica el offset de tu broker. Para los parametros *_epoch de entrada, envia siempre el epoch en segundos.

5.3 Resultado de las ordenes — el punto que mas confunde

Un HTTP 200 no significa que la orden se haya ejecutado. Significa que MT5 recibio la peticion y respondio. Comprueba siempre el campo success (o retcode).
CampoTipoSignificado

5.4 Volumenes y precios

  • El volumen se ajusta al volume_step del simbolo siempre hacia abajo. Redondear hacia arriba aumentaria el riesgo sin que el cliente lo pida. Si el resultado queda por debajo de volume_min, la peticion se rechaza con 400.
  • SL y TP se envian como precio absoluto. En /trading/open tambien se aceptan como distancia en puntos (sl_points, tp_points); si mandas ambos, gana el precio absoluto.
  • Un punto es symbol_info.point. Para EURUSD de 5 digitos, 1 punto = 0,00001, luego 1 pip = 10 puntos.
  • Para quitar un SL o un TP, envia 0. Para dejarlo como esta, envia null u omite el campo.

5.5 Generar el cliente .NET automaticamente

El gateway publica un esquema OpenAPI 3.1 completo (auth + los 41 endpoints de cuenta), con el esquema de seguridad bearerAuth ya declarado:

nswag openapi2csclient /input:http://127.0.0.1:8000/openapi.json \ /classname:Mt5Client /namespace:PythonGetaway /output:Mt5Client.cs # o Refitter refitter --namespace PythonGetaway http://127.0.0.1:8000/openapi.json
Las respuestas de lectura se devuelven como objetos JSON abiertos: los campos que publica MT5 varian entre brokers y builds del terminal, y cerrar el esquema haria que el gateway perdiera campos que el broker si esta enviando. Si prefieres tipos estrictos en .NET, modela solo los campos que uses y deja el resto en un Dictionary<string, JsonElement>.

Abrir posicion a mercado

Ejecuta BUY o SELL a mercado.

El SL/TP se pueden dar de dos formas: como PRECIO (`sl`, `tp`) o como DISTANCIA en puntos (`sl_points`, `tp_points`). Si mandas ambas, gana el precio absoluto. Un punto es `symbol_info.point` (para EURUSD de 5 digitos, 1 punto = 0,00001; 10 puntos = 1 pip).
